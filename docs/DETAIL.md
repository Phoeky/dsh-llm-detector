# 模型指纹检测

让模型凭第一反应写约 300 个 1–355 的整数，再把它的数值分布与冻结的参考库比对，给出
“这个渠道背后最像哪个模型”的排名。检测经 DSH 的 `llm` 服务发出，使用当前 profile
已配置的 provider、认证与适配层。

## 入口

- **左侧边栏「模型指纹」**：用户选择 provider/模型、轮数与并发，开始/取消检测，实时查看
  每条样本的状态与失败原因，以及每轮的候选排名、置信度、序列检查和 token 用量。
  失败或被取消的样本可以单独 **重试**（沿用原提示词，成功后重算该轮结果）。
  默认并发 3，默认展示提示词与原始回答。页面附“两种使用方式”和结果解读说明。
- **对话中使用**：直接对助手说“检测当前模型的指纹”，助手会调用 `llm_fingerprint` 工具；
  也可以指定渠道和模型，例如“检测 codearts 的 deepseek-v4.1-flash-1017 的指纹”。
- 模型工具 `llm_fingerprint`：`action: list` 列出 provider 或模型目录；`action: detect`
  对指定或默认模型采样并评分。UI 与工具共用同一个 Host 作业编排。

## 行为

- 每轮生成 3 道挑战，长度 292–332 不重复，语言独立随机。
- 流式接收；收到要求数量的完整整数即停止（宽松截断），有效数字不足或未正常结束的样本被拒绝。
- 三条有效回答才给校准置信度；一两条只给排名。异常截断（如 `max-tokens`）的回答只参与
  排名，不按完整样本展示校准置信度。
- 结果是参考库内的闭集排序。库外模型也会得到候选，置信度不代表身份证明。
- 每次检测默认发生 3 次真实模型调用，按渠道计费；默认串行发送，单条最长 240 秒。
- 结果只保存在当前 DSH 进程内，重启后清空；响应不包含密钥或接口地址。

## 限制

- 参考库以文字提示词、裸 API 采集；DSH 适配层注入的系统提示可能让结果偏离。
- 同源、蒸馏或共用分词器的模型可能互相混淆。
- 不含分词器探测与图片模式。
